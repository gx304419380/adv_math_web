# 核心原则（最高优先级）

本文件优先级高于其他所有文档。当"好看""省事""快"与这些原则冲突时，以本文件为准。

## 1. 把学生当成什么也不懂的人

这是**第一原则**。写每一段之前，先假设读者：没预习、没听过这个名词、看不懂符号、不知道为什么要学它。

具体做要求：

- **先直觉，后公式，最后才是严格定义**。顺序固定为：生活类比或一幅图 → 它在说什么 → 数学表达式 → 精确定义/定理。不要一上来就甩 ε-δ。
- **禁止思维跳跃**。「显然」「易得」「由上式可知」「不难验证」「略」这类词一律不用；每一步推导都要写出为什么。
- **首次出现的术语必须当场解释**，并用 `strong.term` 标出，不能默认读者认识「去心邻域」「局部保号性」。
- **每个抽象结论都要回答「所以我该怎么想它」**，用 `直观理解` 组件写几何意义或类比。
- **先说结论的用处，再说结论的证明**。学生得先知道这东西能干嘛，才有耐心看推导。

## 2. 能加图的地方就加图

- 任何涉及**函数、几何形状、变化趋势、空间关系**的地方，必须有函数图像或示意图。图优先于文字。
- 每章至少覆盖本节所有主要函数类型；函数相关的每一节都要能看到对应曲线。
- 图必须**自带解读**：图下方用 `直观理解` 或 readout 说明「这条线在表示什么」「拖它会发生什么」，不能只摆一张图。
- 图必须**原创**：用 `assets/js/plot.js`（Canvas 2D）、原生 SVG 或 three.js 绘制，禁止使用教材原图、扫描件或网络图片。

### 2.5 图必须能被学生自己动

- 每张函数图默认**可缩放、可平移**（滚轮 / 双指缩放，拖拽 / 方向键平移，双击或「复位」回到原图）。一张只能干看的小图，等于把「看不清」和「看不全」都留给学生。
- 缩放**不能破坏比例**：等比例是底线（见 §12 与 `COMPONENTS.md` §6）。缩放只改显示窗口，不改 x、y 的像素比。
- 交互后**刻度必须跟着变**：学生要知道自己放大了多少倍、现在看的是哪一段。刻度数字由绘图器统一画，不允许各演示自己手写。
- 参数控制（滑块）和视图控制（缩放平移）**互不覆盖**：换参数才重新取景，重绘不重置视图。写法见 `COMPONENTS.md` §6「frame 与 draw 分开」。
- 能交互的地方**要留看得见的入口**：图下方固定一行「滚轮缩放 · 拖拽平移 − 100% + 复位」，不靠猜。触摸屏上手势要生效，拖动图时页面不能跟着滚。

## 3. 能放动画的地方就放动画

- **动态过程一律用动画**：逼近、累加、旋转、收敛、割线变切线、部分和增长、黎曼和细分……静态图 + 文字描述不算达标。
- 动画要**可播放、可暂停、可回看、可逐步骤**（`assets/js/steps.js` 的 `StepController`）。
- 优先做**可拖动参数**（滑块、拖点、切换按钮），让学生自己试：ε 变小时 δ 怎么变、h 趋 0 时斜率怎么收敛。自己拖出来的结论比看结论记得牢。
- 动画必须尊重 `prefers-reduced-motion`，并提供手动控制，不要自动循环打扰阅读。

## 4. 基于教材，但不复制教材

- **对齐**：章节顺序、节名、知识点名称、数学术语、符号约定、定义与定理的体系，与同济大学《高等数学》第七版（上下册共 12 章）保持一致，方便学生对照课堂进度。
- **原创**：所有讲解文字、类比、示意图形、动画、例题数据、自测题、编号均为本站自撰自绘。
- **绝不收录**：教材正文、例题/习题题干与答案、原书插图、版式、扫描页、PDF 下载链接。详见 [CONTENT_SPEC.md](CONTENT_SPEC.md) 的合规清单。
- 页面显著位置固定标注「非官方学习辅助」与参考书目，声明与同济大学、高等教育出版社无关。
- 数学定义与定理本身是客观事实，可以（也应该）准确表述；受保护的是**文字表达**，所以必须用自己的话重写。

## 5. 纯静态，零使用门槛

- 用户**双击根目录 `index.html` 就能学**：不装软件、不敲命令、不启动服务器、不构建、不 `npm install`。
- 因此**禁止 ES module、禁止 `fetch()` 本地文件、禁止构建步骤**。原因与替代方案见 [MAINTAINER_GUIDE.md](MAINTAINER_GUIDE.md)。
- 公共 CDN 资源需要联网；加载失败要降级显示提示与文字版，不能白屏。
- `bash tools/serve.sh` 只给维护者本地调试和部署用，**不要出现在面向用户的说明里**。

## 6. 全局统一，不许碎片化

- 所有颜色、间距、字号、圆角、阴影等设计 token **只在 `assets/css/base.css` 的 `:root` 中定义一次**，组件一律引用变量。
- 内容组件只用 `design-system.css` 里既定的语义 class（定义 / 定理 / 性质 / 推导 / 例题 / 习题 / 注记 / 直观理解 / 误区），**禁止内联 `style`、禁止在 JS 里动态注入 CSS、禁止另起一套配色**。
- 改一处全局生效；新增章节复用 `chapters/_template/chapter.html`，不要复制粘贴再局部改样式。
- 章节元数据只有 `chapters.json` 一个数据源，导航、进度看板、侧栏都由它驱动。

## 6.5 视觉克制：学术文档，不是营销页

这不是审美偏好，是**注意力预算**问题。学生来是为了看懂一个概念，页面上任何不承载信息的装饰，都在跟内容抢注意力。

- **禁止**：渐变色块、大圆角内容卡片、彩色阴影、卡片套卡片、hover 上浮、装饰性彩色竖条、一个概念配一种颜色。
- **参考对象**：GitHub / MDN / 可汗学院——靠字号、字重、间距、1px 细线建立层级。
- **强调色只做一件事**：标记「可以点」和「当前在哪」。其余一律中性灰。
- **密度可以高**：目录、列表按行密排，比大卡片更容易扫读。
- 细则与完整禁止清单见 [VISUAL_SPEC.md](VISUAL_SPEC.md) §0。

## 7. 数学排版严格合规

数学公式的"格式"本身就是内容。写对了但排错了，学生照样读不懂，甚至读错。

- **该斜体的斜体，该正体的正体**：变量、函数、数列项斜体；函数名（`\sin`、`\ln`、`\lim`）、微分 d、自然常数 e、虚数单位 i、多字母标识符正体。细则见 [MATH_TYPESET.md](MATH_TYPESET.md) §1。
- **页面上绝不允许出现原始写法**：不能露出 `\frac{a}{b}`、`$$`、`\(`、`Σ`、`≤`、`->`、`*`。这些是源码，不是给读者看的东西。技术无法实现时才可以降级，且必须写成可读文本。
- **中文不进公式本体**，只在 `\text{}` 里或移到公式外；中文与公式之间必须有空格。
- 字号、间距、行内/独立公式的比例**只由 `base.css` 的 `--math-*` 变量控制**，禁止在章节里写死。
- `auditMath()` 的控制台警告必须清零才能提交。
- **动态生成的内容同样要合规**：按钮、读数、标签、自测题的数学文字必须走 `texInline` / `texHTML`，禁止用 `x²`、`eˣ`、`1/x` 这类 Unicode 凑出来的写法。Canvas 里只画几何标注，数学表达式一律放到图下读数区。细则见 [MATH_TYPESET.md](MATH_TYPESET.md) §9。
- **证明不折叠**：定理的证明必须直接展开可见，学生不该为了看证明再点一次。折叠只保留给「习题答案」——那是读者自己练题时才想看的。

## 8. 统一术语与记号，全站只有一个说法

学生最怕的不是难，是**同一个东西换了三个名字**。

- 同一个概念全站只用一个术语：定了叫「去心邻域」就不要某处写「空心邻域」。首次出现的写法登记在 [CONTENT_SPEC.md](CONTENT_SPEC.md) 的术语表。
- 同一个符号全站只用一个写法：极限一律 `\lim`，不用 `lim` 混排；ε 一律 `\varepsilon`（不用 `\epsilon`）；无穷小一律 `o(\cdot)` 与 `O(\cdot)` 分清楚。
- 定理编号体系固定：`定义 1.1`、`定理 1.2`、`例 1.3`、`习题 1-1`，站内自用，不冒充教材原编号，且必须注明。
- 新章节开写前先查术语表，缺了就补登记，**不要临时发明新词**。

## 9. 每个抽象结论都必须「落回地面」

不止要有图有动画，还要有**可以自己算一遍的具体例子**。

- 每个定义配一个**数字能算通**的极小例子（如 ε-δ 定义配 f(x)=2x+1、x₀=1，δ=ε/2）。
- 每个定理配一个**不满足条件就失效**的反例。反例比正面例子更能讲清条件的作用。
- 每个易错点单列 `误区` 组件，写清「错在哪一步、为什么看起来对」。
- 例题必须**分步展开**且每步标出依据（用了哪个定理/哪条性质），不能一步跳到底。

## 10. 页面要能被"跳读"

学生不是从头读到尾的，是来找答案的。

- 每节开头一句话说清「这一节解决什么问题」，让人三秒判断该不该往下看。
- 每个组件都有可扫读的标签（定义/定理/性质/例题/误区/直观理解），颜色固定不混用。
- 关键结论用 `mark.key` 高亮，**每节不超过 5 处**，多了等于没有。
- 长章节必须有目录锚点，能直接跳到「例题」「习题」。

## 10.5 复用优先：组件库是唯一来源

12 章内容不可能靠「每次记得写一样」来保持一致，必须靠**结构上只允许一种写法**。

- **先查 [COMPONENTS.md](COMPONENTS.md)，再动手。** 九成情况那里已经有了。
- **同一个东西在两章里必须长得一模一样。** 不一样就是 bug，或者你没用组件库。
- **禁止复制粘贴后局部改样式。** 要改就改组件本身，一处改动全站生效；只在单章出现的样式需求，先问「它是不是应该进组件库」。
- **新组件必须先入库再使用**：加 CSS（只用 `base.css` 的 token）→ 写入 COMPONENTS.md → 在 style-guide.html 加可视化示例 → 同步章节模板。
- **未登记的组件不允许出现在章节里。** 否则半年后没人知道哪个类才是标准的。
- 页面骨架一律从 `chapters/_template/chapter.html` 复制，**不要从上一章的成品页复制**（会把那一章的特例一起带走）。

## 11. 可维护性优先于聪明写法

- 宁写十行直白的 HTML，不写需要构建的三行优雅抽象。零构建是硬约束。
- 新增演示必须在 `demo.js` 里注册进 `DEMOS` 表，并在 `chapters.json` 的 `demos` 字段同步；两处不一致 `check.sh` 会报错。
- 所有路径用相对路径，保证整个文件夹拷到任何地方、任何子目录都能直接打开。
- 不留 TODO 在正文里；未完成的节在 `chapters.json` 标记 `status: "draft"`，导航上显示为灰色。

## 12. 准确比花哨重要

- 公式与数值用 `tools/symcheck.py`（sympy）复核；图形要与公式一致，不能为了好看画错曲线。
- 每章上线前跑 `check.sh` 与 `shot.py`，控制台错误必须为 0。
- 发现错误优先修内容，其次才是美化。

---

**检验标准**：把一个从没学过这节内容的人拉过来，让他只看页面、不提问，能不能自己说出「这个定义大概在讲什么、图里那条线是什么意思」。做不到，就继续改。
